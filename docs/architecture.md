# Architecture

## Layers

```text
Platform capture -> project bundle -> camera engine -> studio preview -> native export
```

- `apps/desktop` is the Tauri 2 shell (Rust, `src-tauri/src/lib.rs`) and the React studio UI (`src/`).
- `packages/core` holds the portable logic shared by preview and export: pointer/zoom types, zoom segment generation, the spring camera track, the frame model, and the per-frame render plan.
- `native/macos-capture` is a Swift command-line sidecar: ScreenCaptureKit capture (`ScreenSwayCapture.swift`) and the GPU exporter (`Exporter.swift`).
- `native/windows-capture` is the Windows sidecar in Rust with the same command line (see "Capture (Windows)").
- `apps/web` is the independent marketing site (static assets on Cloudflare, `apps/site`). It imports `@screensway/core` for its live demo.
- `apps/studio-web` is the browser version (beta), served at `/app/` beside the landing page. It reuses the desktop studio with browser stand-ins for the Tauri commands, records with `getDisplayMedia`, finds the pointer in the video and exports with WebCodecs. See [web-studio.md](web-studio.md).

## Project bundle

```text
~/Movies/ScreenSway/
  Recording-<unix time>.screensway/
    project.json                  manifest: title, createdAt, durationMs, canvas (video pixels)
    media/screen.mp4              H.264 High video, plus one AAC track when system audio and/or the microphone was on
    media/thumbnail.jpg           written by the helper for the library
    media/camera.mp4              the webcam as its own H.264 file, when the camera was on (project.json: media.camera, media.cameraOffsetMs)
    metadata/pointer-events.json  pointer moves and clicks in video pixels, ms on the video timeline
    metadata/keystrokes.json      shortcut chords ({timeMs, keys}) when shortcut capture was on, otherwise []
    edits.json                    studio edits (absent until something is edited): trim, zooms, middle cuts,
                                  redactions, shortcut overlay, camera placement, held framing, chapters
    transcript.json               timed words from speech recognition
    captions.json                 caption lines as edited in the studio, their language and whether they are shown
  Exports/                        (or the folder chosen in Settings, remembered in the app's config folder)
    ScreenSway <date time>.mp4    rendered videos, plus a .gif made from one and the .srt
  Backgrounds/
    <content hash>.<ext>          background images chosen in the studio, plus <hash>.thumb.jpg
  Brand/
    <content hash>.<ext>          the brand kit's logo (the rest of the kit is in the UI's local storage)
```

An imported video (`import_recording`, MP4/MOV/M4V) becomes the same kind of project with an empty pointer log: zooms are added by hand. Everything new is stored as editable project data, never burned into `screen.mp4`.

The pointer is stored as metadata instead of being burned into the video, so the cursor can be smoothed, scaled and given click effects at preview and export time.

## Capture (macOS)

- The helper is driven by the shell through a project-local control file containing `recording`, `pause` or `stop`. It prints `SCREENSWAY_READY` on stderr once frames are flowing, and a JSON summary on stdout when done.
- `SCStream` delivers 420v frames at native pixel density (Retina = 2x points; the long side is capped at 3840 px for H.264). `VideoWriter` encodes them with `AVAssetWriter`: H.264 High, BT.709, about 0.15 bits per pixel per frame.
- Timestamps are rebased so the video and the pointer log share one clock. Paused time is cut from video, audio and pointer data alike. The last frame is repeated at the stop time (ScreenCaptureKit only sends frames on change), and the newest frame is shown on resume. Video and pointer timelines agree within about 10 ms.
- `--system-audio` captures system audio (ScreenSway's own audio excluded); `--microphone <id|default>` captures a microphone through ScreenCaptureKit (`--list-microphones` lists devices). `AudioMixer` places both on the video's clock and mixes them into one 48 kHz stereo AAC track, so every player plays it and export can copy it unchanged. The microphone first goes through `VoiceProcessor`: a 90 Hz high-pass, slow leveling toward -20 dBFS (at most +12 dB), a gentle gate that lowers noise between phrases (noise floor = 10th percentile of the last 3 s), and an instant peak limit. A missing permission is reported as `SCREENSWAY_MICROPHONE_DENIED`; the bundle declares `NSMicrophoneUsageDescription` and the `audio-input` entitlement the hardened runtime requires.
- `--region x,y,w,h` (fractions of the display) sets `SCStreamConfiguration.sourceRect`, so only that area is captured and stored; the pointer log is relative to it.
- `--keystrokes` records shortcut chords (a key with ⌘, ⌃ or ⌥; ⇧ alone is typing) through a listen-only `CGEventTap` on its own run loop thread. It needs Input Monitoring (`--keystroke-access` asks once and prints `true`/`false`); without it nothing is recorded and `SCREENSWAY_KEYSTROKES_DENIED` is printed. macOS hides keys typed into secure (password) fields from event taps. The UI's switch is off by default.
- `--camera <id|default>` records the webcam (`--list-cameras`) with AVFoundation into `media/camera.mp4` (720p H.264), on the screen's clock with the same pauses; `SCREENSWAY_CAMERA_DENIED` reports a missing permission (`NSCameraUsageDescription`).
- `--echo-cancellation` takes the microphone from `AVAudioEngine` with voice processing (macOS removes what the speakers play from the voice; ducking of other audio is kept at its minimum) instead of ScreenCaptureKit, and feeds it, host-timed, into the same `AudioMixer`.
- `--probe <file> [--thumbnail out.jpg]` prints a video's size and length, for importing.
- If ScreenCaptureKit ends the stream (a captured window closes, a display disconnects) or ScreenSway itself quits, the helper finishes and saves the file instead of recording on unattended. An encoder failure (for example a full disk) stops the recording with an error.
- `--list-sources` returns displays and windows with their point size and `pixelScale` (2 on Retina). The UI warns when a non-Retina source is selected, since zoomed-in moments look softer.
- ScreenCaptureKit can drop a shareable-content query when two processes ask at once, so queries time out and retry, and the shell serializes helper launches. A missing Screen Recording permission is reported as `SCREENSWAY_SCREEN_RECORDING_DENIED`; the UI then shows how to grant it.
- Starting a recording runs a 3-second countdown, hides the main window, and shows floating Liquid Glass controls plus a menu bar timer. ScreenSway's windows are excluded from the capture and from audio. Clicks on Pause/Stop are dropped from the pointer log. The controls window is hidden, never closed, when a recording ends: its own Stop request is still waiting for a reply, and answering a request from a destroyed webview raises an exception in WebKit. Release builds keep `panic = "unwind"` so wry can catch such exceptions instead of aborting.

## Capture (Windows)

- `native/windows-capture` builds the same `screensway-capture` helper for Windows (`screensway-capture-x86_64-pc-windows-msvc.exe`), driven exactly like the macOS one: control file, `SCREENSWAY_READY`, JSON summary, the same project bundle. While saving a recording it also names each step on stderr (`SCREENSWAY_SAVING capture|video|audio|camera|details`, repeated about every second during the audio mux); the shell stops a helper whose step has not moved for 120 s, so a stuck save ends with an error instead of "Saving…" forever and the app can record again. The frame callback's errors live outside the frame lock, so a frame stuck in the encoder cannot hide the stop command. The shell code is shared under `cfg(capture)`; only Liquid Glass, System Settings links and the menu bar title stay macOS-only. Recordings live in `Videos\ScreenSway` (`dirs::video_dir()`, `$VIDEO` in the asset scope, which is `~/Movies` on macOS).
- Sources: displays from `EnumDisplayMonitors` (id = device name such as `\\.\DISPLAY1`, primary first) and top-level app windows from `EnumWindows` (visible, not cloaked, not tool windows, not ScreenSway's own; id = window handle). Sizes are logical pixels and `pixelScale` is the Windows scale factor (1.5 at 150 %). The process is per-monitor DPI aware, so cursor, monitor and window coordinates are all physical pixels.
- Frames come from Windows.Graphics.Capture (cursor and the yellow border off). Each frame is copied into a texture the recorder keeps; the D3D11 video processor scales it and converts BGRA to NV12 (BT.709, studio range), and Media Foundation's sink writer encodes H.264 High into MP4 with the GPU encoder when there is one, at the same bitrate as macOS and a keyframe every 2 s. Frames carry their real duration (a frame is written when the next arrives), and the same `VideoTimeline` rules as macOS start the video at zero, cut pauses, refresh the frame on resume and hold the last frame until the stop.
- The pointer is polled every 4 ms (`GetCursorPos`, `GetAsyncKeyState`, honoring swapped buttons) on the same performance-counter clock as the frames; `PointerLog` drops the Pause/Stop click like macOS. The recording ends and is saved when the window or display goes away or ScreenSway quits. The thumbnail is a frame at 0.5 s saved through WIC. `metadata/capture-stats.json` records the encoder Media Foundation chose (hardware or software), frames received and written, and how long frames took to handle, for diagnosing choppy recordings. Helper errors name the step that failed and the HRESULT.
- The recording controls are excluded from capture by `WDA_EXCLUDEFROMCAPTURE` (Tauri's content protection) and paint their own dark background instead of Liquid Glass. The main window keeps the standard Windows title bar.
- Audio: WASAPI loopback and selected microphone share the QPC recording clock, remove paused intervals and mix to one 48 kHz stereo AAC track. Microphone processing applies a 90 Hz high-pass, adaptive gate, slow leveling and peak limiting. Windows microphone privacy errors open the system microphone settings.
- Regions are cropped by the D3D11 video processor before encoding. Shortcut chords are polled with `GetAsyncKeyState` beside the pointer (only with Ctrl, Alt or Win held). The webcam is a `MediaCapture` low-lag recording (`camera.rs`), prepared before the screen starts; its later start is saved as `media.cameraOffsetMs`. `--echo-cancellation` opens the microphone with the communications category, which turns on the device's or Windows' voice processing where available. `--probe` reads a video's size and length with Media Foundation.
- Export: Media Foundation decodes the source and encodes H.264 High; a CPU Lanczos compositor consumes the shared per-frame plan, crop, cursor, rounded masks and caption PNGs. Trimmed audio is re-encoded to AAC. The shell writes the matching SRT.
- Captions: bundled Whisper large-v3-turbo Q5 runs offline on AVX2 CPUs, using normalized 16 kHz mono audio, quiet chunk boundaries and word timestamps. Model setup, validation and performance limits are documented in [windows-validation.md](windows-validation.md).

## Camera, preview and export

- `generateZoomSegments` turns clicks into zoom segments; `buildCameraTrack` simulates a 60 fps critically damped spring camera with a pan dead zone.
- `FrameSettings` (background, frame style, aspect, padding, radius, shadow, quality) → `computeLayout` gives the output size and the window/video rectangles. Each frame style declares its chrome in video widths (title bar, device bezel, laptop base and its overhang), so window, browser and MacBook frames share one fitting rule; the layout also says how the video's own corners are rounded, which the preview and the exporter both use.
- Backgrounds are data (`solid`, `linear`, `mesh`, `waves`, `image`) painted in code, so presets stay sharp at 4K and add nothing to the download. `BUILT_IN_STYLES` are ready-made looks; saved styles live in the UI's local storage. Image backgrounds reference a copy in `Backgrounds/`, read back as a data URL so the export canvas is never tainted.
- `RecordingEdits` holds the trim and the zooms; `zooms: null` means "follow the clicks" (`generateZoomSegments`), an edited list replaces them. `normalizeZooms` keeps zooms sorted, non-overlapping, at least 400 ms and between 1.2× and 3×; `trimRange` keeps at least 500 ms. The camera is always simulated over the whole recording, so a trimmed export shows exactly what the preview shows at that moment.
- Captions: on macOS, `screensway-capture --transcribe video --locale vi-VN --output transcript.json` reads the audio as 16 kHz mono, cuts it into 20–40 s chunks at the quietest moments, skips silent chunks and runs `SFSpeechRecognizer` with `requiresOnDeviceRecognition` on each (macOS 26's `SpeechTranscriber` has no Vietnamese). Windows uses the offline Whisper implementation described above. `buildCaptionLines` groups words into phrases at pauses and sentence ends and splits long phrases into balanced lines, preferring commas. `paintCaption` draws a line with the bundled font for both the preview overlay and the export; the exporter composites the active caption image per frame, and an `.srt` (`toSrt`, shifted by `trimCaptions`) is written next to the video. A missing macOS permission is reported as `SCREENSWAY_SPEECH_DENIED`.
- `buildRenderFrames` produces the per-frame plan: source crop, cursor position and size, click ripple. The preview and the export both follow this plan, so they match. Both get the crop from `buildViewPlan`/`viewAt`: the zoom camera, and in a filled frame (`FrameSettings.fill`, for example 9:16) a view of the frame's shape whose horizontal position follows the pointer with a dead zone (`buildFollowTrack`), held where `edits.framing` segments put it. `safeArea` keeps captions and shortcut keys out of the parts of a vertical video social apps cover; the preview shows them while paused.
- Middle cuts: `edits.cuts` are source-time ranges; `keptRanges` gives what remains, `buildSourceTimes` the source time of every output frame and `sourceToOutputTime`/`outputToSourceTime` map between the two. The preview skips cut parts, captions are clipped and retimed (`retimeCaptions`), and the export job carries `sourceTimesMs` and `sourceRanges`: all three exporters read the frame at each source time and lay the kept audio ranges end to end. Studio edits have a 50-step undo/redo history (⌘/Ctrl+Z, ⌘/Ctrl+⇧+Z); removing a caption line adds a cut that can be undone or restored from the list, and "Suggest cuts for long pauses" adds visible, undoable cuts.
- Redactions (`edits.redactions`) are rectangles in source fractions drawn inside the zoomed content, so they follow zooms; the exporters blur (macOS Gaussian, Windows pixelate) or fill them before the cursor is drawn.
- Overlays: captions, shortcut keys (`paintKeystroke`, shared with the preview), the brand logo and title cards are all PNGs with an output time range in the export's `captions` list. Title cards (`brand.ts`, 2 s on the style's background) add frames before and after the recording; `leadInMs` delays the audio under the intro.
- Webcam: `edits.camera` (`CameraOverlay`: centre, size, circle or rounded, mirror) is placed by `cameraRect`; the preview plays `camera.mp4` in sync and lets it be dragged; the job's `camera` box is filled from the project's camera file by the shell, and both native exporters draw the camera frame at `sourceTime - offsetMs` into a rounded mask.
- After an export: a GIF (`gif.ts`, gifenc: the exported MP4 is sampled frame by frame at 10 or 15 fps, with a size estimate first) saved by `save_export_gif` next to it, `copy_export` puts the MP4 or GIF on the clipboard as a file (AppleScript / `Set-Clipboard`), and export presets (docs 16:9, social 9:16 filled, square) plus saved ones set aspect, fill and quality.
- The background, shadow and title bar are painted by one shared canvas implementation (`packages/core/src/paint.ts`): at screen size for the desktop and landing previews, and at output size for export. The desktop compatibility module in `apps/desktop/src/frame/paint.ts` re-exports it.
- Export: the UI sends the plan plus the painted background and cursor PNGs to `export_recording`. The shell writes them next to the project and runs `screensway-capture --export job.json`. The exporter decodes the recording, composes each frame with Core Image on Metal (edge-extended Lanczos scaling, rounded video mask, cursor, ripple), encodes 60 fps H.264 High, then adds the original audio track without re-encoding. With a trimmed start the job carries `startMs`: the exporter reads from shortly before it and copies the audio from the same moment. Progress is streamed as `export-progress` events.

## Desktop shell commands

Recording: `list_capture_sources`, `list_microphones`, `list_cameras`, `keystroke_access`, `start_recording` (with `systemAudio`, `microphone`, `region`, `captureKeystrokes`, `camera`, `echoCancellation`), `get_storage_status`, `list_interrupted_recordings`, `recover_recording`, `set_recording_paused`, `stop_recording`, `cancel_countdown`, `get_recording_state`. Library: `list_recordings`, `list_transcripts` (speech search), `import_recording`, `resolve_library_project`, `load_recording`, `rename_recording`, `delete_recording`, `reveal_recording`, `read_thumbnail`, `load_edits`, `save_edits`. Captions: `transcribe_recording` (streams `transcribe-progress`), `cancel_transcription`, `load_captions`, `save_captions`, `open_speech_settings`. Backgrounds: `save_background_image`, `list_background_images`, `read_background_image`, `delete_background_image`. Brand: `save_logo`, `read_logo`. Export: `export_recording`, `cancel_export`, `open_export`, `save_export_gif`, `copy_export`, `get_export_folder`, `choose_export_folder`, `reset_export_folder`. Other: `set_native_labels` (menu bar language), `open_screen_recording_settings`, `open_microphone_settings`, `open_camera_settings`, `open_keystroke_settings`. File access is limited to `~/Movies/ScreenSway` and the chosen export folder.

Automation: `screensway://record?source=display|window&audio=1&mic=1`, `screensway://open?project=<folder>.screensway` and `screensway://export?project=…&preset=docs|social|square` (tauri-plugin-deep-link; single-instance passes links to a running app on Windows). The shell emits `automation-request`; the UI asks before any recording starts, and an export runs visibly and can be cancelled. Projects are named by their folder in the library, never by a path.

## Privacy boundary

Recordings, audio, captions and exports never leave the computer, and fonts are bundled. The production Content Security Policy permits bundled content, Tauri IPC and local ScreenSway media through the scoped asset protocol; development additionally permits only the local Vite origins needed for hot reload. There are two documented network exceptions: the signed native updater fetches the static `update/latest.json` manifest after launch or on manual request, and optional usage statistics send batched anonymous event names only after the user agrees. Update downloads must match the public key embedded in the app. The landing page counts visits and downloads without cookies through the same analytics API. The browser version keeps recordings in the tab and sends nothing. Shortcut capture is off by default and stores chords only; a link can never start a recording without the user's confirmation. No recording content or metadata is sent; see `analytics.md` for the event and deployment details.

## Distribution

The helper is bundled beside the Tauri executable as a universal sidecar. Release builds use LTO, size optimization and stripped symbols; the DMG is recompressed with LZMA (`pnpm build:macos`). Builds are ad-hoc signed but not notarized, so first launch needs "Open Anyway"; the landing page, DMG background and release notes explain it. Release CI also creates minisign-protected macOS and Windows updater bundles. Pages publishes those bundles and a static manifest after both platform builds are attached to the release. See [releasing.md](releasing.md).
